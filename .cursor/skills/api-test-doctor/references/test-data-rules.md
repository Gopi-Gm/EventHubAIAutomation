# Test Data Rules

## Principles

1. **Tests must own their data** — create data in `@BeforeMethod`, clean up in `@AfterMethod`
2. **Never use hardcoded real IDs** — IDs change across environments and test runs
3. **Use meaningful, recognizable test data** — prefix names with "TEST_" or "AUTO_" for easy cleanup
4. **Don't rely on pre-existing Petstore data** — the public Petstore API is shared; data is not guaranteed

## Test Data Lifecycle

```java
public class PetTests extends BaseService {
    private PetService petService;
    private long createdPetId;

    @BeforeMethod
    public void setUp() {
        petService = new PetService();

        // Create fresh test data per test
        Pet pet = new Pet();
        pet.setName("AUTO_TestPet_" + System.currentTimeMillis());
        pet.setStatus("available");

        Response response = petService.createPet(pet);
        Assert.assertEquals(response.statusCode(), 200, "Setup: Pet creation failed");
        createdPetId = response.jsonPath().getLong("id");
    }

    @AfterMethod
    public void tearDown() {
        if (createdPetId > 0) {
            petService.deletePet(createdPetId);
        }
    }
}
```

## Test Data Guidelines

| Rule | Reason |
|------|--------|
| Use `System.currentTimeMillis()` for unique names | Avoids name collision across parallel runs |
| Don't assert on `id` values directly | IDs are generated by the API, not predictable |
| Store created IDs in instance variables | So `@AfterMethod` can clean up |
| Use `status` values from: `available`, `pending`, `sold` | These are the only valid Petstore statuses |

## JSON Test Data Files
For complex request payloads, store them in:
```
src/test/resources/testdata/
├── create-pet-request.json
└── update-pet-request.json
```

Load with Jackson:
```java
ObjectMapper mapper = new ObjectMapper();
Pet payload = mapper.readValue(
    getClass().getResourceAsStream("/testdata/create-pet-request.json"),
    Pet.class
);
```

## Public Petstore API Note
The Petstore API at `https://petstore.swagger.io/v2` is a **shared, public sandbox**.
- Data may be deleted by other users at any time
- Don't rely on specific IDs persisting across test runs
- Always create your own test data in `@BeforeMethod`
